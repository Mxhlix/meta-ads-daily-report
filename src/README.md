# Apps Script への設置

`Code.gs` と `appsscript.json` を、Google スプレッドシートに紐づいた Apps Script プロジェクトに入れて使います。

## デモを動かす

1. Google スプレッドシートを新しく作り、拡張機能 > Apps Script を開きます。
2. 既定のコードを `Code.gs` の中身で置き換えます。`appsscript.json` も同じ内容にします（エディタの設定で「マニフェストを表示」をオンにすると編集できます）。
3. `CONFIG.DEMO_MODE` が `true` のまま、関数 `updateAdReport` を実行します。初回は権限の許可を求められます。
4. 起きること:
   - 「広告日次」シートに、前日までの7日分のサンプルの数字が入ります。通信はしません。
   - 列は 日付 / アカウント / 表示回数 / クリック / 消化金額 / CTR(%) / CPC(円) / 成果ごとの列 です。
   - `BREAKDOWN` や `SUMMARY` を `true` にすると、内訳と集計のシートも作られます。
5. もう一度実行しても、日付とアカウントが同じ行は上書きされるので、行は増えません。

デモの数字は決まった値から作るサンプルで、実データではありません。

## 実データに切り替える

1. `CONFIG.DEMO_MODE` を `false` にします。
2. `CONFIG.AD_ACCOUNTS` に広告アカウントを3つまで書きます。ID は `act_` で始まる形です。

   ```
   AD_ACCOUNTS: [
     { id: 'act_000000000000000', label: '本店' }
   ]
   ```

3. 広告アカウントのインサイトを読めるアクセストークンを、スクリプトプロパティ `META_TOKEN` に入れます（プロジェクトの設定 > スクリプト プロパティ）。コードに直接書く `CONFIG.ACCESS_TOKEN` は空のままにします。
4. `CONFIG.CONVERSIONS` に、シートに列として出したい成果を並べます。
   - 標準イベント: `{ label: '購入', type: 'standard', key: 'offsite_conversion.fb_pixel_purchase' }`
   - カスタムコンバージョン: `{ label: 'ボタンタップ', type: 'custom', key: '000000000000000' }`

   標準イベントは `action_type` が `key` と完全に一致したものを数えます。カスタムコンバージョンは `action_type` に `key` の変換IDが含まれていれば数えます。
5. 関数 `updateAdReport` を手で実行し、前日までの直近 `LOOKBACK_DAYS` 日（初期値3日）が入ることを確かめます。当日の分は取りません。

設定に誤りがあると、実行は例外で止まります。止まる条件は、アカウントが空・4つ以上・ID が `act_` で始まらない・成果の指定が不正・トークンが無い・API がエラーを返した・応答が JSON でない・HTTP が200以外、のときです。

## 追加機能のスイッチ

| 設定 | 意味 |
|---|---|
| `BREAKDOWN` | `true` で「キャンペーン別」「広告セット別」シートを作ります |
| `SUMMARY.weekly` | `true` で「週次」シート（月曜はじまり）を日次シートから作り直します |
| `SUMMARY.monthly` | `true` で「月次」シートを日次シートから作り直します |
| `MAIL.enabled` | `true` で最新の週次・月次の集計をメールで送ります |
| `MAIL.to` | 宛先です。空なら実行したアカウントのアドレスへ送ります |

`MAIL.enabled` は、`SUMMARY.weekly` か `SUMMARY.monthly` のどちらかを `true` にしたときだけ使えます。両方 `false` のままメールを ON にすると、毎日の更新とトリガー作成の両方が例外で止まります。

シート名は `CONFIG.SHEETS` で変えられます。

## 毎日の自動更新

1. `CONFIG.SCHEDULE` に時刻（0〜23 の「時」）を書きます。

   | 項目 | 初期値 | 意味 |
   |---|---|---|
   | `DAILY_HOUR` | 8 | 毎日の更新（`updateAdReport`） |
   | `WEEKLY_HOUR` | 9 | 月曜の週次メール（`sendWeeklyMail`） |
   | `MONTHLY_HOUR` | 9 | 1日の月次メール（`sendMonthlyMail`） |

2. 関数 `createTriggers` を実行します。同じ関数の既存のトリガーは消してから作り直します。週次・月次のメールのトリガーは、メールと該当する集計が両方 ON のときだけ作られます。

Apps Script の時間で動くトリガーは、指定した時の1時間の中のどこかで動きます（8 なら 8時台）。分までは指定できません。

トリガーは作った人のアカウントで動きます。そのため、`createTriggers` は実際に使う人が自分のアカウントで実行します。

取得や設定で異常があると、実行は例外で終わります。エラーを握りつぶさないので、実行は Apps Script 上で失敗として残ります。
